# PRD —— 多智能体研究与分析平台（Athena）

## 1 摘要

输入一个研究问题，5 个专业智能体（Planner / Researcher / Analyst / Critic / Writer）基于状态机协作，产出**带引用、可溯源**的结构化研究报告。核心差异化：**每个 Agent 决策可观测、每条结论可溯源、每次回归可评测**——即「Agent 质量工程」。

## 2 背景与痛点

单 Agent 有三大可靠性天花板：不能自我校验、引用可能虚构、失败不透明。2026 年市场对 Agent 人才的要求已从"会搭 demo"转向"可靠 / 可观测 / 可评测"。

## 3 目标（Smart 化）

- 产出报告的结论必须可溯源到证据（引用对齐率基准 ≥0.8）
- 证据不足时必须触发质量回路补充检索，或明确标注风险
- 每次改动通过四维回归门禁
- 轨迹全程可回放（Thought→Action→Observation）

**边界（非目标）**：不做通用聊天助手；不做记忆的长期人格化；只做"研究-撰写"这一窄而深的场景。

## 4 用户与场景

- **主用户**：需要快速、可信、带来源的研究报告的专业人士 / 分析师。
- **场景举例**：(a) 竞品对比 SWOT；(b) 技术路线论证；(c) 市场前景研判。

## 5 交互流程（happy path）

1. 用户输入问题 → 工作台创建任务
2. Planner 拆解为子任务（SSE 推送 agent_start）
3. Researcher 并行检索（Tavily + 本地 RAG），提取带 `[S#]` 来源事实
4. Analyst 交叉验证、矛盾检测
5. Critic 三维打分；不达标**打回 Researcher 带反馈重试**（SSE 可见）
6. 高分风险动作触发 HITL 审批（可配置）
7. Writer 产出带引用的 Markdown 报告
8. reflect 沉淀经验 → 报告与轨迹入库

## 6 四维质量指标（详见 metrics.md）

1. 任务成功率 2. 引用准确率 3. 证据充分性 4. 最终质量（judge 一致性用 Kappa 校准）

## 7 竞品分析

| 维度 | Athena | Dify / Coze | 通用 LLM 直答 |
|---|---|---|---|
| 规划-检索-校验闭环 | ✅ 内建质量回路 | 偏拼装，缺质量评审 | ❌ |
| 结论可溯源 | ✅ 引用对齐 | 有限 | ❌ 幻觉风险高 |
| 质量可评测进 CI | ✅ 四维门禁 | 无 | 无 |
| 轻量可自部署（私有数据） | ✅ | 偏平台 | — |

## 8 工程原则

- **诚实**：任何指标数字必须来自真实评测，不编造。
- **可观测**：每个 Agent 决策与工具调用都产生 span / 事件。
- **成本意识**：模型分级路由（简单任务用小模型）纳入设计。

## 9 里程碑

| 阶段 | 交付 |
|---|---|
| M1 编排+网关 | LangGraph 5-Agent 闭环 + FastAPI(SSE) ✅ |
| M2 能力层 | RAG 混合检索、MCP 工具、HITL、分层记忆 ✅ |
| M3 质量工程 | 评测体系+CI 门禁 ✅ |
| M4 产品化 | 评测看板、工作台、PostgreSQL/pgvector、部署 |

## 10 主要风险与缓解

- **长尾成功率不可控** → 用评测圈定能力边界，低置信度转人工（HITL）
- **多 Agent 循环失控** → 迭代上限 + 预算守卫 + 状态指纹检测
- **Prompt 注入** → 工具输出隔离标记、敏感操作走审批
